# Introduction to Tensors and PyTorch

Imagine you are trying to predict the price of a house. You have two pieces of information: the number of bedrooms and the number of bathrooms. 

In standard Python, you might represent this as a list: `[3, 2]`. If you want to apply some mathematical weights to these features, you could write a quick `for` loop to multiply them.

But what if you are a real estate company trying to predict the prices of 32,000 houses at the exact same time? 

If you use a Python `for` loop to process 32,000 lists one by one, your code will be incredibly slow. To train neural networks efficiently, we need a way to group thousands of numbers into a single solid block, and then perform math on that entire block in one explosive step.

We need a **tensor**.

## The Architecture of Data

A tensor is simply a container of numbers with a specific **shape**. 

Instead of thinking of tensors as advanced mathematical objects, think of them as the physical layout of your data. The shape tells us exactly how the numbers are arranged.

Let's look at how we build these blocks in PyTorch:

```python
import torch

# A single number (0 dimensions)
scalar = torch.tensor(3.0)
# shape: ()

# One house with 3 features (1 dimension)
vector = torch.tensor([3.0, 2.0, 1500.0])
# shape: (3,)

# A batch of 4 houses, each with 2 features (2 dimensions)
batch = torch.tensor([
    [3.0, 2.0],
    [4.0, 3.0],
    [2.0, 1.0],
    [5.0, 4.0],
])
# shape: (4, 2)
```

When you see a line of code like `batch.shape == (32, 2)` in a neural network, it is not just metadata. It is telling you a story:
- We are processing `32` examples simultaneously.
- Each example has `2` distinct features.

If our target prices have the shape `yb.shape == (32, 1)`, it means we have exactly `32` target values, one for each house in our batch.

## Pointing at the Data

Once we have our data packed into a solid block, we need a way to point at specific pieces of it. Because tensors are structured, we can slice them exactly like grids.

```python
# Give me the first house in the batch
batch[0]      

# Give me the second feature (bathrooms) for all houses
batch[:, 1]   

# Give me the first feature of the third house
batch[2, 0]   

# Give me just the first two houses
batch[:2]     
```

## The "Aha!" Moment: Why We Need `@`

Here is where the magic of tensors actually happens.

Suppose we have our batch of 4 houses, each with 2 features. We also have a set of "weights" that tell us how important each feature is. We want to multiply our houses by our weights to get a prediction.

```python
batch = torch.tensor([
    [3.0, 2.0],
    [4.0, 3.0],
    [2.0, 1.0],
    [5.0, 4.0],
]) # shape: (4, 2)

weights = torch.tensor([
    [50.0],  # $50k per bedroom
    [25.0],  # $25k per bathroom
]) # shape: (2, 1)
```

If we try to use standard multiplication `*`, PyTorch will try to match up the numbers element by element. This will either fail completely or give us a tangled mess, because `(4, 2)` and `(2, 1)` are different shapes.

We don't want element-wise multiplication. We want to apply our `(2, 1)` weights to *every single row* of our `(4, 2)` batch simultaneously.

We need **Matrix Multiplication**, represented in PyTorch by the `@` symbol.

```python
predictions = batch @ weights
```

Look at what happens to the shapes:
$$
(4, 2) @ (2, 1) \rightarrow (4, 1)
$$

The inner dimensions (`2` and `2`) snap together and collapse. We are left with a shape of `(4, 1)`: exactly 4 predictions, one for each house. We just processed the entire batch in a single operation, without a single `for` loop.

This exact pattern—`inputs @ weights`—is the beating heart of every neural network layer.

## The Reality Check: Adapting Shapes

In the real world, your data rarely arrives in the exact perfect shape for matrix multiplication. Sometimes the numbers are right, but the Lego blocks won't snap together.

This is why PyTorch gives us tools to bend and adapt our tensors:

```python
vector = torch.tensor([1.0, 2.0, 3.0])
# shape: (3,)

# Add a new "batch" dimension to the front
row = vector.unsqueeze(0)
# shape: (1, 3)

# Add a new dimension to the back
column = vector.unsqueeze(1)
# shape: (3, 1)

# Swap the rows and columns
transposed = column.T
# shape: (1, 3)
```

Whenever a matrix multiplication fails with a "shape mismatch" error, your first instinct should be to check if you need to `unsqueeze` an axis or transpose (`.T`) a matrix to make the inner dimensions line up.
